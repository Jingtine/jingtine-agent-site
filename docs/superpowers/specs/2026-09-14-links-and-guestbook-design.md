# 友链与茶客留言设计

## 目标

为不驚茶坊增加两个长期可维护的交流入口：一个由仓库配置驱动的友链页，以及需要 GitHub 登录的文章评论与公开留言簿。留言公开展示，Jingtine 可在 GitHub Discussions 中删除、锁定或管理内容。

## 范围

本阶段包含：

- 新增“友链”页面，展示朋友网站与常用站点。
- 新增“茶客留言簿”页面，承载全站留言。
- 在每篇公开文章末尾增加“茶后闲谈”。
- 在侧栏增加“来坐坐”分组，并加入“友链”“留言簿”两个入口。
- 为无 JavaScript、第三方脚本失败和评论未配置状态提供可理解的回退。

本阶段不包含账号系统、自建数据库、匿名留言、邮件通知、点赞排行榜或站内管理后台。

## 技术选择

评论使用 Giscus，将留言存储在 `Jingtine/jingtine-agent-site` 的 GitHub Discussions 中。GitHub OAuth 负责登录，网站不接触密码、令牌或用户资料存储。相比把评论写入 Issues，Discussions 更适合长期交流，也不会挤占项目问题追踪。

生产站仍是纯 HTML、CSS 和原生 JavaScript。Giscus 是唯一新增的远程运行时，脚本地址固定为官方 HTTPS 地址；仓库名、仓库 ID、分类名和分类 ID来自仓库内的受信任配置，不接受 URL 参数或远程内容覆盖。

## 信息架构与文案

侧栏保留现有八个主要入口，并新增第三组：

- 来坐坐
  - 友链
  - 留言簿

友链页标题使用“茶友与去处”，说明文字保持个人口吻，不把页面写成工具目录。留言页标题使用“茶客留言簿”，文章评论区标题使用“茶后闲谈”。页脚版权继续使用英文名 `Jingtine`。

## 友链数据与渲染

人工维护的数据放在 `config/links.json`。顶层包含 `groups` 数组，每组包含稳定的 `id`、中文 `name` 和 `links`。每条链接包含：

- `name`：站点或朋友名称。
- `url`：必须是 HTTPS。
- `description`：一到两句介绍。
- `avatar`：可选的仓库本地图片路径。
- `tags`：可选的短标签数组。

`js/links.js` 只使用 DOM 节点、`textContent` 和显式属性赋值渲染配置。外链必须通过 HTTPS 校验，并设置 `target="_blank"` 与 `rel="noopener noreferrer"`。头像路径只能指向 `assets/images/`；缺失或加载失败时显示文字首字母占位。

页面采用松散的刊物式编排：组标题、短说明和两列链接条目，不使用厚重的等宽卡片墙。移动端改为单列。空配置和加载失败分别显示不同提示。

## 评论与留言数据流

新增 `config/comments.json`，保存以下受信任配置：

- `enabled`
- `repo`
- `repoId`
- `category`
- `categoryId`
- `theme`
- `lang`

`js/comments.js` 读取本地配置并校验固定仓库、非空 ID、允许主题和语言。配置有效时，它向指定挂载点添加官方 Giscus 脚本；脚本 URL不由配置决定。配置无效或网络失败时，挂载点显示说明和指向仓库 Discussions 的 HTTPS 备用链接。

文章页在确认文章 slug 存在且文章正文完成加载后再初始化评论，映射键使用 `article:<slug>`，避免标题修改后丢失讨论。留言簿使用固定映射键 `guestbook`。两个入口共用同一 Discussion 分类。

评论区采用懒加载：挂载点接近视口时才加载 Giscus；键盘用户聚焦“加载评论”按钮时可立即加载。这样不会让第三方脚本阻塞文章正文。

## GitHub Discussions 前置条件

目标仓库必须启用 Discussions，并创建一个允许普通 Discussion 的分类“茶客留言”。实施时读取仓库当前状态并取得仓库 ID与分类 ID；若无法取得，不写入虚假 ID，页面保持明确的“留言功能尚未完成配置”回退状态。

Giscus GitHub App 需要安装到目标仓库。安装属于 GitHub 账户权限操作，应在本地页面、配置和测试全部完成后，作为最后的外部配置步骤单独执行。

## 安全与隐私

- 不接受匿名提交；发言需要 GitHub 登录。
- 网站不存储登录态、访问令牌、邮箱或 IP。
- 评论内容由 Giscus iframe 渲染，不进入站点 DOM，也不通过 `innerHTML` 注入。
- 所有友链配置和错误文本按不可信字符串处理。
- 远程脚本来源固定，不从配置拼接脚本 URL。
- 页面明确提示留言公开可见，并链接到 GitHub Discussions。

## 渐进增强与可访问性

无 JavaScript 时，友链页保留页面说明与配置不可用提示；留言区保留前往 Discussions 的普通链接。评论加载按钮可通过键盘触发，状态变化使用 `aria-live="polite"`，加载中和失败状态不移动焦点。

侧栏新增入口沿用现有移动菜单、焦点管理和 `aria-current` 规则。所有新增页面包含跳转正文链接、主导航、主内容和页脚。

## 检查与测试

`scripts/check.py` 增加友链和评论配置检查：HTTPS 外链、唯一分组 ID、本地头像存在、固定仓库、必需评论 ID以及新增页面和导航入口。

Playwright 覆盖：

- 友链正常、空数据、配置失败、恶意文本和不安全 URL。
- 文章评论只在有效文章加载后初始化，并使用稳定 slug 映射。
- 留言簿使用固定映射。
- Giscus 配置失败和脚本失败回退。
- 键盘加载、无 JavaScript导航、移动端无横向溢出。
- 新增入口在所有主页面中的导航一致性。

最终运行 Python 单元测试、`scripts/check.py`、相关 Playwright 测试和完整 Playwright 回归。

## 完成标准

- 友链页可通过编辑 `config/links.json` 长期维护。
- 文章评论与留言簿都要求 GitHub 登录，公开展示，并可由 Jingtine 在 Discussions 中管理。
- 未配置或第三方不可用时，正文、导航和备用入口仍然可用。
- 网站继续满足静态 GitHub Pages、无生产构建步骤和浏览器安全约定。
