# Jingtine Agent Site 个性化改版设计

## 目标

将现有偏通用的浅紫、浅蓝科技作品集升级为具有鲜明个人气质的中文个人网站。新版以用户提供的温室插画为全站氛围背景，使用 Apple 风格的半透明玻璃、柔和景深、大留白和细腻动效，同时保留现有内容体系、静态站点架构和核心交互。

改版应让访客首先认识 Jingtine 本人，随后看见他正在构建、思考和阅读的内容，并能自然进入项目、博客、Wiki、论文、阅读器和知识助手。

## 设计原则

1. **个人优先**：首页左侧延续当前头像、姓名、身份标签和介绍，不把个人信息让位给纯装饰。
2. **进行时表达**：首页右侧通过“正在构建”“正在思考”“最近阅读”呈现持续成长状态。
3. **背景服务内容**：插画只提供朦胧色彩和轮廓，不承担信息表达，也不与头像和文字竞争。
4. **中文优先**：导航、栏目、状态、按钮和反馈信息主要使用中文；品牌名、GitHub、RSS 和必要技术名词保留英文。
5. **统一而非复制**：页面共享同一套背景、玻璃组件和排版令牌，通过层级和密度区分页面。
6. **渐进增强**：背景、模糊和动画失效时，内容、导航和交互仍然可用。

## 视觉体系

### 背景

使用用户提供的 `OplusInfoCollection_260408162811357.png` 作为源图。实施时将优化后的网页副本保存到 `assets/images/`，不修改桌面上的原始文件。

背景采用双层处理：

- 底层铺满视口，轻微放大并使用较强模糊，让画面只保留温室、天空、白花和人物的大致轮廓。
- 上层使用白色雾化渐变、局部亮度调节和轻微边缘暗角，保证不同区域的文字对比度。
- 背景在全站固定复用；不同页面只调整蒙层和玻璃层级，不更换背景图。
- 移动端单独设置裁切位置，避免主体轮廓集中在文字背后。

### 色彩与材质

主色从背景提取：奶油白、鼠尾草绿、天空蓝和灰绿色。现有浅紫保留为交互强调色，不再主导整个界面。

玻璃组件使用半透明浅色填充、细高光边框、柔和阴影和有限的 `backdrop-filter`。必须提供不依赖背景模糊的半透明实色回退，保证不支持该属性的浏览器仍有足够对比度。

### 排版

继续优先使用系统字体栈，以获得接近 Apple 平台的清晰排版和无需外部字体的加载稳定性。中文标题使用更大的字号、更紧凑的字距和更强的层级；正文保持舒适行高。代码、时间和状态缩写可以使用现有等宽字体。

## 首页

### 首屏布局

桌面端采用左右分栏：

- 左侧延续现有首页的显示设计，包括头像、问候语、姓名、身份描述、技能标签和个人简介；内容改为左对齐，并置于一个克制的主玻璃区域中。
- 右侧排列三张错落但对齐清晰的状态玻璃卡：“正在构建”“正在思考”“最近阅读”。
- 顶部导航改成悬浮胶囊式玻璃条，当前页面拥有明确状态。
- 首屏之后继续展示核心能力、精选项目和最新文章，避免新版只剩视觉展示。

移动端变为单栏：个人介绍在前，三张状态卡在后。卡片不依赖悬停才能阅读。

### 动效

保留现有头像和滚动引导的核心体验，删除或弱化与新设计不一致的全局流星和随机粒子。新版动效限定为：

- 极轻的背景景深漂移；
- 玻璃高光随指针产生有限变化；
- 页面内容随滚动柔和浮现；
- 状态卡之间的小幅层次位移。

所有动效必须确定、克制且不影响阅读。`prefers-reduced-motion: reduce` 下关闭漂移、视差和装饰性过渡。

## 页面体系

### 关于

使用个人档案式玻璃面板，重点呈现南京大学、软件工程、工商管理双学位和 AI Agent / 产品创新方向。技能信息继续复用共享标签和面板组件。

### 项目

使用大尺寸项目橱窗强化重点项目，降低平均分布的小卡片带来的模板感。项目名称、价值说明、角色和技术信息保持清晰层级。

### 博客与 Wiki

采用中文内容索引布局，标题是主要视觉元素；标签、日期、阅读时间和关联内容为次级信息。Markdown 渲染安全边界保持不变。

### 论文与阅读器

保留较高信息密度，统一使用磨砂玻璃列表和分段筛选。远程数据加载中、为空或失败时显示明确中文状态。

### 知识助手

将助手表现为进入个人知识花园的入口。聊天区使用独立浮层和清晰的消息层级，但不改变现有数据来源与问答逻辑。

### 状态页

保留仪表盘结构，弱化背景装饰并提高玻璃不透明度，优先保证状态名称、更新时间和错误信息的辨识度。

### 导航与页脚

导航主要使用中文页面名，并保持所有现有入口。移动端保留菜单按钮、键盘操作、焦点管理和 ARIA 状态。页脚保留 `Jingtine`、GitHub、Email、RSS 和站点状态入口。

## 组件边界

本次不引入框架或模板系统。共享视觉通过现有 HTML 类名和 `styles.css` 中的设计令牌实现：

- 背景与全局蒙层；
- 悬浮玻璃导航；
- 主玻璃面板与次级玻璃卡；
- 状态卡；
- 页面标题区；
- 内容列表与项目橱窗；
- 按钮、标签、筛选器和空状态。

页面行为继续放在 `js/` 下的独立文件中。与背景景深和玻璃高光有关的通用行为由 `js/site-motion.js` 管理，导航继续由 `js/nav.js` 管理。动态内容脚本继续使用 DOM 节点构造和 `textContent` 渲染不可信数据。

## 响应式与可访问性

- 桌面端首屏左右分栏，平板和手机端收束为单栏。
- 小屏提高玻璃不透明度并降低背景对比，避免文字落在复杂画面上。
- 所有交互保留可见焦点、语义化 HTML、键盘访问和正确 ARIA 状态。
- 外部链接继续验证 HTTPS，并使用 `rel="noopener noreferrer"`。
- 背景图是装饰，不传达必须信息；CSS 背景加载失败不影响页面理解。
- 颜色与玻璃透明度需要满足正文和关键控件的可读性要求。

## 失败与回退

- 背景图加载失败时显示奶油白到浅蓝绿色的静态渐变。
- 浏览器不支持 `backdrop-filter` 时使用更高不透明度的浅色面板。
- JavaScript 或动画初始化失败时，所有内容默认可见且导航可用。
- 动态数据加载失败时显示页面现有或改进后的中文错误状态，不抛出未捕获异常。

## 验证

实施完成后至少执行：

1. `python scripts/check.py`；若无 `python` 命令则使用 `py -3 scripts/check.py`。
2. `npx playwright test --config tests/playwright.config.js`，前提是本地测试依赖已安装。
3. 检查桌面、平板和手机宽度下的首页、内容索引页和一个动态数据页。
4. 检查键盘导航、移动菜单、减少动画模式、背景图失败回退和动态数据错误状态。
5. 确认所有站内链接与 GitHub Pages 的 `/jingtine-agent-site/` 路径规则兼容。

## 非目标

- 不引入 React、Vue、Astro、打包器、服务端代码或生产运行时依赖。
- 不改变博客、Wiki、RSS、论文和阅读器的数据生成架构。
- 不重新抓取远程数据，也不手工修改生成文件。
- 不把背景插画中的人物作为站点内容或身份信息使用；它只作为氛围背景。
- 不追求对 Apple 网站的逐像素复制，只采用其克制排版、玻璃层次、留白和细腻动效原则。
