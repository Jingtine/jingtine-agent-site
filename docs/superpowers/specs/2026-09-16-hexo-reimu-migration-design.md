# Hexo Reimu Migration Design

## Summary

Migrate Jingtine Agent Site in place from a directly served collection of hand-written HTML, CSS, JavaScript, Markdown, generated JSON, and Python data jobs to a Hexo-generated static site using `hexo-theme-reimu`.

The deployed site remains static and stays at `https://jingtine.github.io/jingtine-agent-site/`. The repository changes from being the deployable artifact itself to being the source for a reproducible Hexo build. GitHub Actions generates and deploys the `public/` artifact whenever `main` is updated.

The new site preserves the “不驚茶坊” identity, Jingtine's existing avatar, writing, project information, about information, and friend links. It adopts Reimu's page structure and core interaction model without using the theme's Touhou character artwork.

## Goals

- Use the official npm distribution of `hexo-theme-reimu`, pinned through `package.json` and `package-lock.json`.
- Keep the existing GitHub repository, GitHub Pages project URL, and `/jingtine-agent-site/` base path.
- Preserve the nine current public articles, their dates, titles, summaries, tags, and categories where those fields map cleanly to Hexo.
- Preserve the existing site name, author identity, avatar, project content, about content, and friend-link content.
- Replace the current page shell with Reimu's responsive layout, sidebar, article cards, archives, taxonomy pages, dark mode, table of contents, local search, loading transition, lazy loading, and back-to-top interaction.
- Use a light blue, pale purple, and white palette, with a low-saturation blue-purple dark theme.
- Use the user-provided Nanjing University photograph as the default article cover.
- Continue publishing an RSS/Atom feed generated by Hexo.
- Remove the features and automation that no longer belong in the simplified site.

## Non-goals

- Do not preserve the old hand-written HTML layout or its JavaScript application architecture.
- Do not preserve old article URLs such as `article.html?slug=...`.
- Do not preserve or migrate comment discussions; there are no existing comments to retain.
- Do not add Giscus, Waline, another comment provider, or a guestbook.
- Do not enable Live2D, custom cursors, mouse fireworks, Material You color extraction, or a music player in the initial release.
- Do not choose per-article cover art in the initial release.
- Do not deploy any server-side runtime, database, or comment API.

## Information Architecture

The public navigation contains:

1. Home
2. Archives
3. Categories and tags
4. Projects
5. About
6. Friends
7. RSS/Atom

Local search is available through Reimu's built-in Hexo search integration. There is no comments or guestbook navigation item.

The following current experiences are removed:

- RSS aggregation reader
- arXiv paper library
- Wiki/digital garden
- knowledge assistant
- status/GitHub activity page
- guestbook and article comments
- legacy `knowledge.html`, `library.html`, and `contact.html` compatibility pages

## Hexo Source Structure

The implementation uses conventional Hexo paths:

```text
source/
├── _data/
│   ├── avatar/
│   └── covers/
├── _posts/
├── about/
├── projects/
├── friend/
└── images/
```

- `source/_posts/` is the sole source for public articles.
- `source/about/index.md`, `source/projects/index.md`, and `source/friend/index.md` hold the retained standalone content.
- Friend-link records move from `config/links.json` to the Reimu-supported friend data format beside the friend page.
- The current avatar is copied into the Reimu avatar data directory.
- Site-owned visual overrides and images live under `source/`; a Reimu-supported head injection loads the generated custom stylesheet, and no files inside the installed npm theme are edited.
- `_config.yml` owns Hexo site, URL, permalink, feed, and generation settings.
- `_config.reimu.yml` owns Reimu presentation and feature settings.

The official Reimu package is installed rather than vendored under `themes/`. Exact dependency versions are committed in both npm manifest and lockfile so a clean `npm ci` is reproducible.

## Article Migration

Each `articles/*.md` file becomes one file in `source/_posts/` with the existing stable filename used as its Hexo slug. TOML front matter is converted to YAML. The following mappings are retained:

- `title` → `title`
- `date` → `date`
- `summary` → `description`
- `category` → `categories`
- `tags` → `tags`
- filename → stable `slug`
- `draft` → placement in `_posts` or `_drafts`; only current public articles are part of the initial public migration

Wiki-style `[[...]]` references and paragraphs whose purpose depends on the removed Wiki are deleted, as approved. Ordinary prose and independent links remain intact. No old query-string route or redirect shim is created.

The new permalink pattern is `/posts/:title/`, beneath the configured GitHub Pages project root. Feed entries, archives, tags, categories, and internal links all use the new canonical URLs.

## Visual Design

Reimu supplies the base templates and interaction behavior. The site adds narrowly scoped, site-owned style overrides rather than forking the theme.

### Identity and palette

- Site title: `不驚茶坊`
- Author identity: `不驚醴 / Jingtine`
- Existing avatar is retained.
- Light theme: white surfaces with pale blue and pale purple accents.
- Dark theme: low-saturation navy, blue, and purple surfaces with accessible text contrast.
- Reimu's red accent tokens are overridden consistently; controls retain visible hover and keyboard-focus states.

### Enabled behavior

- Responsive Reimu navigation and sidebar
- Dark mode
- Article table of contents
- Archives, categories, and tags
- Local search
- Loading transition
- Image lazy loading
- Code-copy interaction
- Previous/next article navigation
- Back to top
- Reduced motion behavior for users who request it

### Disabled behavior

- Reimu/Touhou character artwork
- Reimu custom cursor
- Mouse firework effects
- Live2D
- Material You dynamic color extraction
- Music player for the initial release

The music-player settings remain disabled and documented in `_config.reimu.yml`. A future change can enable APlayer or Meting after the user selects audio; the initial site does not load player scripts or render an empty player.

## Image Strategy

The supplied Nanjing University photograph is the initial global article cover. Its source resolution is 2275 × 1279, which is close to 16:9.

During implementation it is:

- cropped minimally to an exact 16:9 composition;
- exported as an optimized WebP;
- stored locally as `source/images/default-campus-cover.webp`;
- configured as Reimu's global fallback cover for articles without an explicit `cover` field;
- positioned so that the building entrance remains visible under responsive cropping;
- given only a subtle blue-purple treatment, without text, characters, or branding baked into the bitmap.

Existing posts receive no individual cover selection. A separate site banner remains a neutral blue-purple local placeholder until the user supplies a banner image. Replacing the banner or adding a per-post `cover` later must not require template changes.

## Comments and Guestbook

The migrated site has no comments or guestbook.

- Do not configure Giscus or Waline.
- Remove `config/comments.json`, `js/comments.js`, comment tests, comment markup, and the guestbook page.
- Do not add comment-provider client scripts or network requests.
- Do not mutate or delete GitHub Discussions in the remote repository; they simply cease to be embedded by the site.

## Removed Sources and Automation

Delete sources, generated outputs, browser code, checks, and documentation that exist solely for removed features. This includes the relevant portions of:

- paper, Wiki, reader, assistant, status, guestbook, and legacy redirect HTML pages;
- `content/wiki/`;
- paper, feed aggregation, Wiki, assistant, status, GitHub-stat, and comment configuration/data;
- browser scripts dedicated to those features;
- Python collectors/generators dedicated to those features;
- generated JSON and OPML outputs dedicated to those features;
- nightly remote-data refresh workflow;
- tests and fixtures that assert removed behavior.

Removal must be dependency-driven rather than extension-driven: shared assets are retained if any surviving page uses them. The old generated `feed.xml` is removed from source because Hexo generates the new feed.

`README.md` and `AGENTS.md` are rewritten to describe Hexo authoring, the Node-based production build, the new directories, and the new validation commands. They must no longer claim that the repository is directly deployable without npm.

## Build and Deployment

The outer Hexo configuration uses:

- site URL `https://jingtine.github.io/jingtine-agent-site/`;
- root `/jingtine-agent-site/`;
- Chinese locale and Asia/Shanghai timezone;
- `/posts/:title/` permalinks;
- Reimu as the selected theme;
- a generated Atom or RSS feed linked from Reimu.

A GitHub Pages workflow triggers on changes to `main` and on manual dispatch. It:

1. checks out the repository;
2. installs the declared Node version;
3. runs `npm ci`;
4. runs the repository's verification command;
5. generates the Hexo site;
6. uploads `public/` as the Pages artifact;
7. deploys using the official GitHub Pages actions.

The workflow has only the permissions required for Pages deployment and uses deployment concurrency so a newer deployment supersedes an obsolete queued run safely.

The generated `public/` directory is a build artifact and is not committed.

## Validation

The migration is complete only when all of the following pass from a clean dependency install:

- Hexo configuration validation and a production `hexo clean && hexo generate` build.
- A repository check that asserts the expected generated routes and rejects removed routes or removed feature references.
- Link validation for the `/jingtine-agent-site/` project root.
- Feed parsing and verification that all nine public posts appear with canonical URLs.
- Playwright coverage for desktop and mobile home, post, archive, projects, about, and friends pages.
- Playwright coverage for navigation, dark mode, sidebar, table of contents, local search, reduced motion, and keyboard focus.
- A network or DOM assertion that no comment provider is loaded.
- Visual inspection of the default cover crop in desktop and mobile cards and post headers.
- A clean-worktree review confirming that only the intended Hexo source, configuration, workflow, documentation, tests, and local assets remain.

## Acceptance Criteria

- The deployed project URL loads without broken CSS, JavaScript, images, or root-relative links.
- The site visibly uses Reimu's layout and interaction model while retaining the “不驚茶坊” identity.
- The palette is light blue and purple, with usable light and dark themes.
- All nine migrated articles render from Hexo Markdown and no Wiki references remain.
- The supplied campus photograph is the optimized default article cover.
- Projects, About, and Friends preserve the meaningful current content.
- Archives, categories, tags, local search, and RSS work.
- Papers, Wiki, reader, assistant, status, comments, and guestbook are absent from navigation and generated output.
- The GitHub Actions Pages workflow builds and deploys from `main` without committing generated `public/` output.
